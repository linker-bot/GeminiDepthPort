# Offline u16 depth output v1

`depth-output` consumes a u16 depth view with a declared representation, explicit byte order and row stride, and a versioned frame context. It never claims to recover original SDK counts from quantized millimetres. Zero remains invalid, 65535 is valid, padding is ignored and truncated or oversized layouts fail before encoding. PNG stores 16-bit grayscale numeric values in PNG network byte order without normalization or colorization.

`FrameRecord.kind` distinguishes `original_millimetres`, `d2c_color_z_millimetres` and `original_sdk_counts {scale_mm}`. Native counts retain their integer values and explicit positive finite millimetres-per-count scale; the encoder performs no unit conversion. Callers must bind that declaration to the actual source evidence. Normalization and D2C are upstream operations, described in the [offline tool reference](../../crates/offline-depth/README.md).

Call `encode` once and reuse the resulting immutable `EncodedDepth` for directory/TAR output. A per-frame JSONL manifest records ordinal, original source clocks, dimensions, unit, native-count, original-millimetre or D2C-color-Z interpretation, pair evidence digest, snapshot binding, PNG digest and canonical little-endian u16 pixel digest. Ordinals start at zero and advance exactly; a job cannot mix snapshots or identity contexts. The caller must verify supplied snapshot and association evidence before starting the job; a digest alone is a reference, not proof of association.

`bounded_queue` uses a blocking synchronous channel. It does not drop old frames and is independent from realtime preview queues. `Job` writes into a unique private `<name>.partial` directory; directory images, archive and manifest share that staging location. PNG data is compressed only once when both outputs are requested. All files are created exclusively; frame files and completed outputs are atomically renamed. The final directory is published with Linux/macOS no-replace rename; targets are never overwritten. TAR, JSONL and COMPLETE are only finalized after all frames succeed, followed by file/directory sync. Parent and staging location must be on one filesystem. Unsupported platforms return an explicit error rather than weaken the atomic guarantee.

Errors poison append state and retain the incomplete directory for diagnosis. No TAR continuation is supported; retry with a new job name. A sync failure after the final rename returns `CommitUncertain` with the final path; inspect that output rather than silently retry or overwrite it. `.partial` is always incomplete even if a finish failure left a COMPLETE file inside. Completion requires the final path plus COMPLETE, a complete archive and the manifest.

Validation covers pixel-exact PNG decode (zero/max, little/big endian, padding), directory/TAR encoded-byte equality and archive EOF, binding failure poisoning, explicit write failure and blocking queue behavior. No throughput, hardware or SDK-comparison claim is made.
