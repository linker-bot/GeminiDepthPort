# 验证记录

## 预览、确认与标定绑定复查（2026-10-28）

本轮修复以下遗漏：

- 预览版本原先只绑定相机字段，共享 ROS domain 或镜像配置变化后仍可能通过确认。现使用与确认相同的完整相机/共享配置摘要，旧的未确认预览需重启。
- 检查出帧或停止预览期间发生的外部文件编辑，可能被旧快照覆盖。Web、CLI 和确认流程现在保留读取版本，并在最终原子替换前再次核对原始库存字节。
- 确认现在针对固定预览容器 ID 执行探针，结束时核对实例仍一致；执行前刷新会话租约，避免探针期间到期。
- 标定收集前后核对同一组驱动容器 ID，拒绝同 generation 标签下重建实例混入的证据。
- 实机复现了预览容器默认 root、cap_drop=ALL 与用户私有配置权限冲突。现对齐创建者 UID/GID，并使用可写的 /tmp HOME/ROS_HOME。
- 有效管理 POST 刷新活动时间，空闲回收在获取操作锁后再复核，避免新启动预览被旧的空闲判断删除。

已完成：15 项 Rust 管理测试（1 项内部 HTTP 活动测试、14 项契约测试）、25 项本地 CLI/HTTP 测试，Rust workspace 和 Python 原有离线检查通过。Ubuntu amd64 环境上先前版本的 23 项 CLI/HTTP 和 5 项隔离 Linux 模拟已通过；新增预览 UID/GID 策略场景纳入现有 Linux 模拟脚本，最终镜像回归由 CI/后续串行测试继续验证。

真实硬件证据：Rust 正确识别 Gemini 335L，并拒绝将 Gemini 305 绑定为 Gemini 2。固定公开 SDK 的短时原生彩色/深度采集通过布局、时间戳递增与有效深度检查；修复身份后，ROS 调试预览、JPEG 接口及实际档位确认通过。具体绑定、档位、图像和诊断保持在受控测试目录，不进入仓库。

标准采集镜像构建在 ROS 依赖索引连接处失败；受控测试镜像使用相同固定源码、补丁及合成校验，通过显式依赖清单完成构建。不能将其记录为标准 Dockerfile 在该环境已构建成功。

正式启动随后遇到非本次测试容器持有设备，健康检查正确拒绝整组就绪。本轮未获得正式启动、真实标定导出、录制保护闭环或长期多机验证的成功结论；依用户要求等待其他测试结束后再继续。

## Rust 管理复查与修复（2026-10-28）

在 PR #10 合并后的主分支检查默认管理实现，补充异常输入、失败恢复与 Linux 编排回归。发现并修复：

- CLI 忽略停止命令后的 `--help` 和未知选项；现在帮助请求不执行命令，多余/重复/缺值选项在设备操作前被拒绝。
- generation 文件清单可缺失，且相机列表未与启用库存核对；现在检查部署文件全集、服务身份、元数据及实际启用相机集合，拒绝部分配置冒充整组就绪。
- 工作任务中的外部子命令超时只结束父进程，后代仍可能持有输出管道；现在每条命令有独立进程组，Rust 任务收到终止后先清理内部命令，再由外层限时终止。普通 Compose 命令截止时间从一小时收紧到一分钟。
- 重复/遗漏的 Docker inspect 结果和缺失运行状态可能被接受；现在按请求 ID 集合、唯一性和状态类型检查，归属不明时拒绝停止。
- 损坏库存会触发 panic；现在在持久化和 Web 状态路径返回受控错误。配置不满足启动要求时清除此前遗留的 `ready=true`。
- 旧版 Web 保存遗漏格式、尺寸/FPS、曝光开关及曝光/增益范围校验；补回这些限制。镜像引用不能以选项前缀开头，设备枚举也先验证库存。
- 设备枚举输出被丢弃、HTTP 自检把分段状态行误判失败；已恢复枚举输出并按完整状态行解析。
- 同一部署可被多个 Web 服务同时接管；增加独立的生命周期服务锁，CLI 操作锁保持可用。
- 标定 ROI 的 null/非对象及非零或错误类型裁剪值被忽略；现在拒绝这类证据。
- generation 激活末尾失败时可能删除已被指针引用的目录；改为保留不可变版本，避免生成悬空引用。该项经过静态路径检查，未注入真实文件系统 fsync 故障。

本轮回归：12 项 Rust 管理契约测试、19 项 Rust CLI/HTTP 黑盒测试，原有 47 个配置对照及迁移/标定摘要继续通过。原有 Python 测试运行 180 项，通过，2 项环境相关跳过；整个 Rust workspace 测试和 Clippy 检查通过。

新增 `tests/rust/test_linux_lifecycle.py`，在无网络、无 Docker socket、无真实 USB 的 Linux 管理容器内挂载合成 sysfs 与 Docker 测试程序，验证真实 Rust 预检及编排：全部配置先校验、逐台启动/探测、整组复查、健康复用、保护凭证释放，以及中间设备失败后保留已启动实例并阻止后续设备启动。2 项场景通过，并加入 CI。

Linux arm64 管理镜像构建和原有非 root/只读 HTTP 冒烟通过。PR #10 的远端 CI（包括完整官方驱动及合成 SDK/ROS 测试）已全部成功；本轮修复由后续 PR 的 CI 重新验证。

以上仍不包含物理三机、USB 热插拔、长期采集或标定精度验收，不将模拟健康探针视为真实出帧证据。
