# 官方驱动的原生 YUYV 发布适配

本修改复用官方 OrbbecSDK_ROS2，不另写设备驱动。官方 SDK 本来支持 YUYV；适配解决的是 ROS 发布阶段保留 YUYV 字节的问题。

## 来源与修改范围

公开基线和补丁摘要记录在 `patches/public-orbbec/manifest.json`。

官方基线的彩色 YUYV 路径会转换为 RGB8。适配后，彩色 YUYV 使用原始 ROS Image 发布器，跳过 RGB 解码与 image_transport 的隐式颜色转换；RGB、MJPG 等其他发布路径继续保留。

ROS Humble 的标准编码常量没有 `YUYV` 成员，cv_bridge 也不应被假定支持字面值 `yuyv`。因此原始路径直接构造拥有独立数据的 `sensor_msgs/Image`，明确填写 `encoding="yuyv"`、紧密行步长与原有 SDK 时间戳/光学帧。其他工具若不能识别该接口编码，必须在消费端显式转换，不能静默改正式话题格式。

变更不增加 SDK 访问进程，不改变既有话题命名，也不替换设备内参、时间来源或坐标系。官方已有的有界队列、溢出日志与队列统计服务原样沿用，不重复打补丁。

## 缓冲区与实际格式检查

- 在解码和发布前核对实际 SDK 帧格式；请求 YUYV 却收到其他格式时拒绝该帧，不能把其他字节标成 YUYV。
- 彩色尺寸必须为正、宽度为偶数；检查乘法溢出、ROS 载荷上限、空指针及源缓冲区长度。
- 发布消息的数据使用独立拥有的字节数组；SDK 帧被释放或复用后，已构造消息仍保持有效。
- 当前固定 SDK 没有公开的行步长读取接口。驱动只接受长度与紧密 YUYV 布局完全相符的输入，遇到无法确认的填充或额外数据直接拒绝，不通过除法猜测 stride。
- 共享复制函数可接受调用方提供的可信行步长，逐行排除填充；该能力经过合成测试，但不代表当前驱动能够识别未知 SDK 填充。

SDK/固件不支持请求档位时，沿用官方明确拒绝配置的行为。实际编码或布局不匹配时，运行健康检查也不会把相机组报告为就绪。

## 预览和组合限制

Web 预览增加 YUYV 到 BGR 的显式转换，再编码 JPEG；只转换预览副本，不改动正式 ROS 载荷。驱动的 PNG 保存同样在视图副本上转换。

原生 YUYV 与在线 D2C、彩色点云、彩色去畸变、翻转、旋转或增强深度等组合尚未验证，管理配置和运行适配器拒绝相应请求。正式链路保持原始图像与原有离线处理边界。

管理器在预览和正式启动时核对镜像能力与实际消息。已验证范围见[验证索引](../validation/README.md)。

## 构建与来源核验

`apply_public_yuyv_patch.py` 先验证公开基线、补丁摘要与原文件摘要，再执行 Git 补丁检查和应用，最后核对输出摘要。未知版本、源文件漂移、补丁漂移和重复应用都会失败。工具隔离父仓库发现，避免嵌套目录中 Git 静默跳过补丁。

镜像构建依次执行：

1. 获取并固定公开上游源码。
2. 验证并应用公开补丁，记录来源摘要。
3. 编译官方 ROS 驱动。
4. 执行带内存检查的独立 C++ 缓冲区测试。
5. 使用官方 SDK FrameFactory 构造合成帧，检查格式和释放后的数据独立性，不创建 Context/Pipeline。
6. 检查合成 ROS 消息往返及真实 OpenCV JPEG 预览。

只有这些构建步骤全部成功才生成带原生 YUYV 能力声明的最终镜像。镜像还记录补丁摘要；预检同时核对能力与期望摘要，旧镜像或摘要不符不能冒充已适配镜像。

构建环境、发行版、CPU 架构及镜像依赖仍需要按实际构建验收。基础镜像和系统依赖未完全按 digest 锁定，补丁来源核验不代表完整可重现构建或第三方许可审计。

## 验证边界与公开信息

合成测试验证缓冲区边界、所有权、序列化、编码与预览；它们不证明某台设备的档位、曝光、USB 带宽、图像质量、持续稳定性或与机器人状态的时间对齐。

真机验收必须检查实际 ROS 消息及正式录制结果。禁止发布真实设备标识、配置、标定、保护凭证、生成版本或现场日志。公开报告只记录方法与经审查的结果。

公开源码参考：[官方 ROS 2 驱动](https://github.com/orbbec/OrbbecSDK_ROS2)、[官方 SDK](https://github.com/orbbec/OrbbecSDK_v2)。
