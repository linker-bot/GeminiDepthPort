# 2026-10-28 Rust 采集服务验证记录

305 与 335L 各完成一次完整 **1800 秒严格 ROS 消费测试**，随后各完成一次约 5 秒的真实 ROSbag2 录制与离线读回。本文只解释已完成的消费、录制、资源和状态采样；不包含正式管理流程或官方驱动性能对照的成功结论。

完整脱敏数据见 [JSON 记录](rust-service-validation-20261028.json)。原始图像、实际设备标识、绑定、标定矩阵、私有配置和 SDK 日志没有进入本报告。

## 产物与方法

两个设备使用相同的冻结镜像与 SDK 2.10.6。固定的公开上游为 OrbbecSDK_ROS2 commit `c153462518ad674650bafa4464fda72c27ab797a`；SDK、ROS bridge、service 二进制与消费工具源码摘要均记录在 JSON。导出时，两份运行记录指向的原始 runtime manifest 仍逐字节匹配，未使用后续构建替换长测指纹。

这次长测对应的消费源码 SHA256 为 `ef5f80a9cfdf697e38dd6c11a9c2747ba22bc3687881989e5addfa5d287afef2`。以后即使工具增加功能，也不能将新版本冒称为本次长测实际运行的源码。服务二进制指纹不等于已记录了一个完整源码提交；本报告不推断不存在的源码 commit。

每个设备由独立服务和独立消费容器组成，host network、private IPC；ROS Humble/Fast DDS 使用仅允许回环接口的显式 UDP transport，`ROS_LOCALHOST_ONLY=0`。消费端关联每路 Image、CameraInfo、frame_metadata 与 RGBD pair_metadata，核对编码/布局、标定数值、深度单位声明、会话、时间、源序号及配对，并实际延迟订阅静态 TF。未进行三机合并部署或跨相机曝光同步验收。

## 完整 1800 秒消费结果

- **305**：彩色、深度各接收并关联 54,040 帧；匹配 54,039 对。两路 active FPS 约 30.022，契约错误、超过规定间隔的图像 gap 和观察到的源序号跳值均为 0。
- **335L**：彩色 53,935 帧、深度 53,937 帧全部关联；匹配 53,935 对。两路 active FPS 约 29.964，上述三类错误同样为 0。

两者实际发现并检查了 Image、CameraInfo、frame_metadata、pair_metadata 以及静态 TF 所需的 QoS，静态 TF 迟订阅均通过。QoS 图检查与本次消费配齐结果共同构成证据，不是把发布调用次数当成订阅端交付。

305 彩色/深度的平均接收 age 分别约 7.99/7.87 ms，P99 直方图桶上界均为 20 ms，最大值约 62.39/122.45 ms。335L 分别约 6.30/21.41 ms，P99 桶上界为 20/33 ms，最大值约 49.69/98.82 ms。JSON 保留完整固定桶边界和计数；桶计数总和已核对等于各路图像数。

**age 是消费回调接收 Unix 时间减已发布的 SDK system Unix stamp，不是物理曝光到算法的端到端延迟。P99 数值是固定桶上界，不是精确分位数。** Active FPS 使用第一至最后一帧的接收时间，不是将计数简单除以完整窗口。

窗口尾部最多补齐 0.2 秒关联消息，不纳入新图像延长帧率窗口。305/335L 分别剩余 4/5 个未配齐组件，关联缓存淘汰均为 0。这些窗口边界差异不是已证明的掉帧数；源序号未跳值也不能单独认证整条采集链无丢帧。

## 真实 ROSbag2 记录与读回

每台设备在长测和资源采样结束后各录制约 5 秒，原始像素只保存在私有 ROSbag2。305 两路图像各 150 帧；335L 彩色 149 帧、深度 150 帧；静态 TF 与各类 metadata 均实际入 bag。两者各成功关联 149 对，契约和流错误均为 0。

读回逐 topic 核对消息数及实际序列化字节的流式 SHA256，结果均 byte-exact。之后进行消息反序列化、YUYV 参考解码、LE u16 深度读取，以及 header、标定和 metadata 关联检查。录制首尾的组件数允许不同，不能将它们解释为已经测定的设备丢帧。

这是实际录制及离线读回证据，不是 `ros2 bag play` 重新发布或业务后处理程序兼容认证。离线读回没有伪造 live QoS 或 TF 迟订阅结果；相应在线证据来自前面的完整消费测试。

## 独立的资源与状态采样窗口

资源采样实际持续 **1740.001 秒，871 个样本，约 29 分钟**。范围只有两个服务和两个消费者的四个 cgroup，不是整机 CPU、USB 中断或全部内核工作量。CPU 单位是逻辑核等效值，1.0 表示一个逻辑核持续占用，不是整机 100%。

- 305 服务：平均约 0.2725 逻辑核；cgroup memory 首末约 34.06→35.17 MiB，采样峰值约 36.41 MiB。
- 335L 服务：约 0.3185 逻辑核；41.03→43.04 MiB，采样峰值约 44.25 MiB。
- 305 消费者：约 0.2172 逻辑核；36.70→40.18 MiB，采样峰值约 41.54 MiB。
- 335L 消费者：约 0.2156 逻辑核；37.30→40.08 MiB，采样峰值约 41.27 MiB。

四个 cgroup 的 OOM kill 计数均为 0。这里的 memory **包含 cgroup 计入的 cache**，不是进程 RSS。JSON 同时保留窗口采样峰值与 cgroup lifetime peak；后者可包含窗口外启动阶段，不能冒充窗口峰值。首末和四分位均值有轻微增长，本次记录不构成无内存泄漏认证。

状态采样是另一个 **1680.000 秒、约 28 分钟**的窗口，每台 841 次读取，均为 ready，无状态采样错误、会话变化或重启次数增量；发布失败和拒绝对数的增量也均为 0。它验证的是离散采样的服务状态，不能替代持续 ROS 消费或保证两个采样点之间绝无短暂变化。

## 当前结论边界

本记录支持：在这两台设备、这组冻结产物和明确消费契约下，完整 30 分钟消费及独立短 ROSbag2 读回通过。资源和状态窗口分别是 29 与 28 分钟，不能将它们改称 30 分钟完整采样。

它不认证三机部署、物理深度精度、硬件曝光同步、机器人业务消费方兼容或无内存泄漏；也没有提供官方驱动同负载性能对照，因此不支持任何 Rust CPU/内存/延迟收益百分比。正式管理流程、故障恢复和后续性能试验须各自附上独立结果，不能从本次消费通过推导成功。
