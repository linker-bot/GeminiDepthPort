# 四机 RGB-D 五分钟复测（2026-10-29）

## 结论与边界

北京时间 00:22:53–00:27:53，四台并行采集 300.003 秒。四路严格 ROS 消费
验收均通过：图像、CameraInfo、源帧元数据、配对元数据及迟订阅 TF 均通过
原有检查。四路均无重启、无发布失败、无时间戳提交失败。

这不是“所有输入零异常”：两台 Gemini 2 各有 5 个缺单路的 frameset 被整对
拒绝；151 次状态采样中有一次短暂 degraded，最后四路质量状态均为 normal。
335L 的一个真实样本在 D2C 后超出 u16 毫米范围，按约定整帧失败，未生成
COMPLETE。没有通过截断、钳位、丢点或放宽阈值使其成功。

脱敏机器结果见 [JSON](four-camera-5min-20261029.json)。不包含设备序列号、
采集身份、原始像素、私有标定或宿主路径。原始证据留在测试机私有目录。

## 环境与固定条件

- 原生 Linux 测试机，四台共用一个 5 Gbps USB 3 Hub；固定公开 SDK 2.10.6。
- Gemini 305、335L：彩色 YUYV 640×480，深度 Y16 640×480，均 30 FPS。
- Gemini 2 两台：彩色 YUYV 640×480，深度 Y16 640×400，均 30 FPS。
- 各机独立 Pipeline、序列号绑定、采集会话、命名空间与实际 SDK 标定快照。
- 深度明确 normalize-mm；配对使用设备时钟、最大偏差 20,000 us。
- 原有消费阈值保留：最低 27 FPS、至少 8,000 帧/对、最大时间间隔 0.5 秒、
  新鲜度 1 秒，single-session。没有为本轮降低阈值。
- 整对实时队列容量 2，自动重启预算 0，3 秒预热。逐台就绪后进入四机并行窗口。
- 宿主 USBFS 从实测 16 MiB 调为 256 MiB；即时修改，未写永久配置。

## 已定位与修正

1. 多发布器 `/tf_static`：订阅深度 1 的迟订阅读队列会淘汰其他发布者的样本。
   真实 ROS 四个合成发布器回归复现了 1/4 与 4/4 的区别。严格消费器与 ROSbag
   工具统一使用有界深度 100；发布器 QoS 不变，回归进入 ROS CI。
2. 第四台启动退出：私有错误为 `UVC_ERROR_NO_MEM`，而不是 serial 重复、Rust
   单位转换或缺少档位。增加当前 USBFS 上限后，四台统一版本均成功冷启动。
3. Gemini 2 全零：独立 C++ SDK 单机对照同样读到几乎全零。用户调整现场后，
   两台 SDK 单机短测全部帧都有非零深度，非零像素约 72%–84%；未改相机属性
   或图像内容。随后完整窗口继续逐帧扫描，排除“只取一个正常样本”的误判。
4. 增加 owner-only 私有失败记录，以便诊断 SDK 错误。最终实现限长 4096 字符、
   0600 文件，公开状态与 stderr 仍脱敏；记录失败不覆盖原始错误。
5. D2C 错误保留 `WARP_FAILED` 分类并增加 `detail_code=D2C_OUTPUT_OVERFLOW`，
   不改变既有溢出规则。CLI 回归验证原始输入不变、失败非零且无假完成标记。

## 窗口结果

- Gemini 305：发布 8,999 对，29.996 FPS；严格消费匹配 9,006 对，TF 收到。
- Gemini 335L：发布 9,001 对，30.003 FPS；严格消费匹配 8,989 对，TF 收到。
- Gemini 2 A：发布 9,001 对，30.003 FPS；严格消费匹配 9,001 对，缺路拒绝 5 对。
- Gemini 2 B：发布 8,991 对，29.970 FPS；严格消费匹配 9,001 对，缺路拒绝 5 对。

生产者采样与各消费器使用独立计时窗口，故计数不是相同帧集合，不能相减当作
传输掉帧。消费者各自观测 300 秒，新增证据采样 310 秒；没有跨会话拼接。

新增配对证据共收到 9,302 / 9,284 / 9,297 / 9,297 条，校验错误均为零。
对应深度流逐帧抽查 9,302 / 9,284 / 9,297 / 9,298 帧，全部有非零像素。
两台 Gemini 2 的非零比例分别为 71.6%–74.8% 与 82.9%–84.4%。非零不等于
物理精度认证，也不能替代距离参考测量。

## 离线与数值核对

四台各保留一份按真实深度 header 关联的完整像素、原始配对证据及快照。
四份 validate-only、原始 PNG/TAR 输出均成功；独立解码逐像素等于源 u16，
目录 PNG 与 TAR 内 PNG 字节相同，快照及证据副本与输入一致。

305 和两台 Gemini 2 的 D2C PNG/TAR 完成并通过同样的归档/副本核对。
335L 样本有 576 个 65535 边界值；其变换后的获胜 color-Z 不能用 u16 毫米
表示，实际 CLI 返回 D2C_OUTPUT_OVERFLOW，整个输出不完整。该负例保留，
不将 SDK 的 65535 擅自改为零，也不宣称所有真实输入都能生成毫米 D2C。

所有本次采集与消费容器结束后均已停止。初次线缆/场景问题、测试目录/入口
准备失败均独立留档，未计入上述正式窗口。未进行物理标定精度、硬件曝光同步、
SDK D2C 差异或 30 分钟长期稳定性验收。
