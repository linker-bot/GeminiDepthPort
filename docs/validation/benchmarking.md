# 性能对照协议

目前没有成功的官方驱动同负载性能对照，不提供 Rust 收益百分比。
已有资源采样见[验证索引](README.md)，不能据此推导语言迁移收益。

## 对照条件

固定并记录源码提交、镜像 digest、实际加载的 SDK 摘要、固件、USB 拓扑、
主机硬件及系统版本。两侧使用相同的档位、输出编码、深度单位、时间语义、
ROS/RMW、QoS、传输配置和消费工具。滤波、同步、属性写入及队列差异必须
单列，不能用相同输出配置摘要冒充内部处理完全相同。

使用 A/B/B/A 交替重复，分开记录预热、发现、正式采样和恢复窗口。
同一消费者执行 standard-wire 验收；Rust 扩展 metadata 另作严格验收。
任一正确性检查失败，该轮不能成为成功性能样本。

## 指标与报告

- 采集和消费者分别采样 cgroup CPU、memory、OOM；另测整机负载。
- 区分 cgroup memory、进程 RSS、窗口峰值与 lifetime peak。
- 记录 FPS、接收间隔、源序号变化、拒绝对、发布失败及重启。
- 接收 age 是接收时间减源 system stamp，不是曝光到算法延迟；直方图
  P99 应标明桶上界，不能作为精确分位数。
- 记录温度、有效频率、后台负载、退出状态与所有失败轮次。

每轮保存私有 manifest、原始观测与资源结果；公开摘要仅保留复核必需的
产物指纹、方法、汇总和限制，不含设备身份、实际绑定、图像或标定。
报告须区分实测结果、静态载荷计算和假设；编码变化带来的字节减少不属于
语言加速。仅 SDK 探针不能与完整 SDK/ROS/DDS 服务直接比较。
