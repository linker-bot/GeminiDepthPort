# 三相机配置模型与迁移

本次实现对应[阶段二清单](geminidepthport-phase-two-checklist-public.md)的修改包 A。

修改包 B 已补充[三机配置生成与生命周期编排](generation-lifecycle.md)，schema v2 可生成独立部署并进入检查式启动路径。驱动原生 YUYV 适配见 [修改包 C](native-yuyv.md)；Web 已支持按配置列表编辑、预览与实际档位确认；[标定快照](calibration-interface.md)与[消费侧语义探针](acceptance.md)分别验证结构及所列数据语义，仍不能据此宣称真机集成完成。

默认 `inventory.json` 已切换为 schema v2 三个 RGB-D 槽位，均未绑定、禁用且未填写档位，不含现场配置。旧版双机配置继续兼容，历史示例只保留为测试夹具。CLI 与 Web 均通过实际预览/健康检查确认档位，不直接置位确认标志。

## 新模型

`configuration.py` 负责 schema 校验、确认摘要、配置变更失效和纯迁移预览；`driver_profiles.json` 是依据公开上游 launch 参数建立的型号目录。型号选择与逻辑位置分离，同一型号可以绑定多个逻辑相机，但不能自行指定 launch 可执行文件。

每台相机分别声明：

- `name`：逻辑标识，仅用于管理。
- `profile`：受支持的公开驱动配置标识。
- `namespace`：显式绝对 ROS 命名空间，不从逻辑名称推导。
- `frame_prefix`：显式坐标系前缀；通过组件启动适配器与命名空间分别绑定。
- `serial_number`：受控设备绑定；公开模板为空。
- `enabled`：是否参与采集，启用设备必须已绑定。
- `parameters`：型号目录允许的驱动参数；身份、数据源和路径类受管理字段禁止注入。
- `timestamp_source`、`calibration_revision`：受控的时间与标定声明。
- `depth_unit`：公开接口要求的毫米单位。
- `health`：受控检查策略。
- `profiles_verified`、`verification`：确认结果及其配置摘要，仅用于绑定实际检查结果。

启用数量可以是一至三台。没有启用设备时允许草稿编辑，但严格校验返回 `NO_ACTIVE_CAMERAS`，不会报告采集就绪。彩色必须请求 YUYV，深度必须请求原始未对齐的数据格式。图像真实字节、深度尺度和实际硬件支持仍需后续运行时检查。

`inventory.v2.example.json` 仅为三台未绑定、禁用设备的离线模板，不提供采集档位和标定。顶层兼容字段来自本仓库已经公开的示例，未引入任何消费方配置。模板不能直接启动设备。

## 离线校验

在已安装项目依赖的环境执行：

```sh
python3 cameractl.py validate --file inventory.v2.example.json --draft
```

输出只包含校验状态、schema 版本、启用数量和硬件验证标记。`--draft` 允许未确认的配置，不代表设备健康。省略 `--draft` 时，启用相机必须携带与当前配置相符的检查证据。

确认摘要涵盖设备绑定、命名空间、坐标系前缀、型号、档位、时间、标定和共享运行字段。通过保存入口修改配置会清除受影响的确认；共享运行字段变化会清除全部确认。仅改另一台相机不会使本台确认失效。

直接编辑受控文件或伪造证据不属于可信检查流程。摘要用于检测漂移，不是数字签名或身份认证。schema v2 使用显式命名空间生成预览绑定，以实际消息和 QoS 检查确认档位；确认不代替标定精度、深度尺度和消费方时间验收。

## 兼容迁移

迁移工具只读取受控环境当前的旧版 inventory，不从其他项目导入信息。

```sh
python3 cameractl.py migrate
```

默认只返回摘要和 `plan_digest`，不写 inventory、不导出原始参数。迁移规则：

1. 保留旧逻辑标识及已知的旧版生成命名规则，显式写入原命名空间与 frame 前缀。
2. 保留已绑定设备，不猜测位置，不自动添加第三台设备。
3. 示例占位符转为未绑定、禁用状态。
4. 将彩色目标格式明确设为 YUYV，并清除全部旧确认。此操作是配置转换，不证明驱动已原生发布 YUYV。
5. 标定适用性保持待重新确认，不将历史确认作为新接口验收结果。

如需改变逻辑标识或保留自定义旧绑定，通过 `--bindings` 指定受控映射文件。映射以旧逻辑标识为键，每条必须完整提供 `name`、`namespace`、`frame_prefix`；不接受部分映射字段，也不推断左右位置。映射文件不得提交到仓库或附入公开报告。

只有核对迁移预览后才应用：

```sh
python3 cameractl.py migrate --apply --expected-plan <plan_digest>
```

使用映射时，预览与应用必须传入相同的 `--bindings` 文件。源文件字节或映射发生变化后，旧摘要将被拒绝。

应用前要求正式设备及调试预览已停止。工具先在被 Git 忽略的 `state/migrations/` 保存原文件精确备份，再原子替换 inventory；备份和新 inventory 的权限为仅文件所有者可读写。备份失败不修改原文件，替换失败保留原文件及备份。操作通过现有 CLI 操作锁串行化。

迁移应用会将 inventory 切换为需要重新确认并核验镜像接口能力的 schema v2。需要继续使用旧运行方式时，应在受控环境恢复迁移前备份；恢复后原有生成文件若与 inventory 不匹配，应按旧版流程重新生成。不得通过改 schema 数字伪造回退。

## 验证边界与保密

离线测试使用合成设备身份和合成图像档位，覆盖三机组合、绑定冲突、格式限制、失效证据、迁移漂移、备份失败、原子替换和优化模式下的校验。

不得提交真实 inventory、绑定映射、迁移备份、标定或运行快照。公开迁移输出不包含设备身份或原始参数；原始异常及外部命令输出不应进入公开错误。

已补充公开驱动的原生 YUYV 构建适配，但没有启动实际相机或验证真实图像。后续工作从标定物理精度和受控真机端到端验收继续，不应将本修改包标为完整集成完成。
