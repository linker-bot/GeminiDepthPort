# GeminiDepthPort 阶段二修改清单（公开版）

状态：修改包 A 的配置模型与兼容迁移，以及修改包 B 的生成与生命周期编排已实现，见[配置说明](configuration-v2.md)与[生命周期说明](generation-lifecycle.md)。修改包 B 通过离线和合成部署验证。修改包 C 已加入公开官方驱动的最小适配、来源核验及合成测试；完整驱动构建与真机验收尚未确认完成，其他修改包仍待实施。

依据：[相机数据接口约定（公开版）](camera-interface-public.md)。

## 1. 范围与信息边界

目标：支持三台相机独立管理及同时出流，发布符合公开接口的原生 YUYV，保持消费方既有话题绑定、录制和后处理链路。

本阶段仅规划 GeminiDepthPort 的修改，不修改消费方业务代码，不部署实际设备。支持较少设备的启用组合；三台同时启用是必测场景。

本文中的文件名来自 GeminiDepthPort 公开源码；新增文件标注为“新增建议”。不引用任何消费方内部源码、补丁、配置或运行数据。不得将本地补丁直接复制进公开提交；原生 YUYV 的实现从公开驱动接口和本文契约独立设计。

示例只使用抽象字段及合成数据。设备身份、实际命名空间、档位、通信环境、标定和部署绑定均由受控环境提供，不附入公开清单。

## 2. 修改包 A：三机配置模型与兼容迁移

修改：`inventory.json`、`cameractl.py`；新增建议：`configuration.py`。

- [x] 升级配置 schema，取消固定双角色及恰好两台启用的限制，支持一至三台启用设备；零台为未配置状态，不能报告采集就绪。
- [x] 分离逻辑标识、驱动型号配置、设备绑定、ROS 命名空间和 frame 前缀，不再由角色名拼接实际话题。
- [x] 将型号到 launch 文件及可用参数的映射集中管理，允许多个逻辑相机使用同一型号，不允许任意指定可执行文件。
- [x] 校验逻辑标识、命名空间及 frame 前缀冲突；启用设备绑定必须唯一、非空且不是示例占位符。
- [x] 定义本阶段彩色接口模式为原生 YUYV，拒绝配置静默降级；深度启用时要求原始坐标系及毫米尺度。
- [x] 修改设备、命名空间、档位、时间或标定相关配置后，使原确认结果失效。
- [x] 档位确认必须基于当前配置的实际检查结果；CLI 不得仅修改确认标志绕过验证。
- [x] 旧配置迁移先生成预览及备份，不自动推断新增相机身份、左右位置或实际话题绑定；有歧义时保持未确认。
- [x] 使用显式校验异常和稳定错误分类，不依赖可被解释器优化禁用的 `assert` 承担运行时校验。

完成标准：合成三机配置可通过校验；重复绑定、命名冲突及不兼容格式被拒绝；迁移不静默改变既有绑定。

## 3. 修改包 B：生成配置与三机生命周期

修改：`cameractl.py`、`compose.yaml`、`config/`、`deployment_control.py`、`deploy.sh`、`systemd/orbbec-stack.service.in`。

- [x] 通过同一启用设备列表生成驱动配置、健康检查、容器服务与启动顺序，消除固定双机名称及数量分支。
- [x] 容器服务身份与 ROS 名称分别生成；所有数据话题、内参、TF 和诊断端点使用明确绑定。
- [x] 按确定顺序逐台启动，每台通过实际出帧检查后继续，最后复查全部必需流。
- [x] 启动失败返回部分结果和整组未就绪；保留诊断状态，禁止报告全部成功。
- [x] 停止以实际运行实例及已生效配置为准，防止配置中禁用或删除设备后遗漏旧容器。
- [x] 重复启停保持安全；相同配置且已健康的启动请求不隐式先停机。
- [x] 配置生成采用临时产物、完整验证和原子切换；失败保留上一份有效产物。清理过期生成文件时仅处理受管理文件。
- [x] 绑定、保存、生成、启停、预览和开机恢复共用操作锁及录制保护检查；任何入口都不得绕过。
- [x] 设备发现、健康探针和状态查询不额外打开设备；调试驱动与正式驱动保持互斥。
- [x] ROS 发行版、通信实现及发现策略按公开兼容矩阵选择，具体运行值从受控配置注入；已校验生成结构与探针 QoS，真实同机跨容器通信仍需目标主机验收。

完成标准：三机配置可生成且能按预期调度；模拟任一必需设备失败、配置变化及重复调用时状态准确；无遗留驱动重复占用设备。

## 4. 修改包 C：驱动构建与原生 YUYV 发布

修改：`Dockerfile`、`runtime/validate_runtime.py`、`runtime/launch_camera.py`；新增建议：`patches/`、构建校验脚本。

- [ ] 从公开驱动源码选择并固定经验证的构建基线，记录源码与补丁摘要；不得引用消费方的私有版本或本地构建参数。
- [x] 先核验公开基线是否已支持原生 YUYV；仅对缺失能力编写最小补丁，不盲目叠加已有实现。
- [x] 验证设备和 SDK 返回的是实际 YUYV 帧；不支持时拒绝启动并返回档位不支持，不自动改成其他格式。
- [x] 在正式发布路径跳过不必要的 RGB 解码，发布 `sensor_msgs/Image`，保持 `encoding=yuyv`、偶数宽度及 `Y0 U Y1 V` 字节顺序。
- [x] 检查源缓冲区边界；有可信行步长时逐行打包为 `step=width×2`。当前 SDK 无 stride 读取接口，驱动拒绝未知填充，不猜布局或伪造载荷长度。
- [x] 消息拥有有效数据生命周期，不能在发布后引用已被 SDK 回收或复用的帧缓冲区。
- [x] 保留源帧时间和既有坐标系绑定；不得以发布时间替换图像时间戳。
- [x] 限制采集队列，暴露可观测溢出与异常，不通过无限排队掩盖处理不足；具体容量不写入公开文档。
- [x] 构建检查补丁适用性、重复应用和实现契约；镜像与受控运行快照可追溯到公开源码及补丁摘要。
- [x] 更新运行时校验：不再强制命名空间等于角色加固定后缀，按明确配置和实际 launch 参数进行校验。
- [x] 彩色与深度格式以实际消息为最终判据；仅配置为 YUYV 不算通过。

当前：已核验公开基线及补丁摘要，C++ 内存检查与真实 OpenCV 合成预览通过；完整驱动构建、ROS 往返及真机检查待确认。

完成标准：公开驱动构建通过；合成数据验证字节布局及缓冲区生命周期；真机实际发布的消息通过接口检查。静态源码检查不能替代真机验证。


## 5. 修改包 D：健康检查、时间与标定

修改：`runtime/health.py`；新增建议：`runtime/image_contract.py`、`runtime/calibration_export.py`。

- [ ] 共用消息校验函数，检查彩色编码、尺寸、步长、载荷长度及深度编码、步长、大小端。
- [ ] 从 SDK 尺度或经验证的驱动语义确认毫米单位；必要时在提供方转换。仅检查 `16UC1` 无法证明单位正确。
- [ ] 核验启用流与对应 CameraInfo，检查光学 frame 一致性、尺寸及标定有效状态；未标定不得伪装有效。
- [ ] 检查时间戳非零、连续推进、回退与重置；通过时间来源声明验证时钟映射，区分接收新鲜度与采集时间。
- [ ] 校验 frame 绑定及 TF 语义，取消依靠固定角色字符串前缀判断坐标系有效性的逻辑。
- [ ] 按受控门槛检查实际接收帧率、断流与异常；禁用流不参与检查，零启用设备不满足就绪条件。
- [ ] 从已运行驱动服务或可信缓存导出所需外参，写明源/目标坐标系、方向、旋转表示及平移单位，不重复打开设备。
- [ ] 绑定或档位变化后重新核验标定适用性，避免旧缓存跨配置复用。
- [ ] 明确探针检查范围：不把时间戳推进或整组健康解释为硬件曝光同步。

完成标准：畸形载荷、错误格式、时间回退、失效标定及断流均能定位；实际深度单位有独立验证依据。

## 6. 修改包 E：结构化控制接口与录制保护

修改：`cameractl.py`、`deployment_control.py`、`web_server.py`；新增建议：`recording_guard.py`。

- [ ] 提供版本化 JSON 控制接口，覆盖能力查询、状态、配置快照、启停、获取保护及释放保护；命令名称在实现时统一定义。
- [ ] 状态区分未配置、停止、启动中、就绪、降级和失败；保护状态单独表达，不与采集健康混为一谈。
- [ ] stdout 仅输出结构化结果，诊断写入受控通道；错误码稳定，不能将原始子进程输出直接拼入公开错误。
- [ ] 在同一原子保护检查内核对运行版本并建立录制保护；阻止“检查通过后、开录前被另一入口重启”的竞态。
- [ ] 保护期间拒绝影响采集的保存、生效、生成、停机、重启与调试操作；只读查询保持可用。
- [ ] 保护记录持久化且与持有方关联；正常释放必须匹配持有凭证，不在日志或响应样例中暴露凭证。
- [ ] 管理进程重启后恢复保护；持有方失联进入待确认状态，不因租约超时自动解除。恢复流程需确认录制已结束并保留审计记录。
- [ ] 不可变运行快照绑定实际生效配置、构建和标定版本；草稿修改不能覆盖运行快照。
- [ ] 私有状态包含必要运行信息；公开导出按字段白名单生成，只保留允许公开的接口版本、状态及错误分类。

完成标准：并发 CLI/Web/开机流程不能绕过保护；管理进程重启后保护有效；结构化输出可以被消费方稳定解析。

## 7. 修改包 F：三机 Web 配置与 YUYV 预览

修改：`web_server.py`、`web/app.js`、`web/index.html`、`web/style.css`、`runtime/preview_bridge.py`、`runtime/preview_session.py`。

- [ ] 从配置和能力结果动态显示启用设备，不保留固定双机数组、按钮和文案；覆盖三台独立绑定和状态显示。
- [ ] 从明确命名空间订阅，取消由角色拼接话题；保留配置 revision 检查和设备确认失效机制。
- [ ] `preview_bridge.py` 增加严格 YUYV 解析，仅在预览端转换为 BGR 并编码 JPEG；不重新发布或覆盖正式原始图像。
- [ ] 预览拒绝畸形载荷，断流或格式错误时停止展示旧帧，不能以成功生成过 JPEG 代表当前健康。
- [ ] 保护状态由后端执行，前端禁用对应按钮仅作为提示，不能作为唯一限制。
- [ ] 本阶段保留调试预览与正式采集互斥；不引入另一套业务录制或正式预览网关。
- [ ] 三机预览会话独立回收，但回收预览不得影响正式采集实例。
- [ ] 管理界面与公开导出边界明确；公开截图和测试报告只能使用合成数据。

完成标准：三机界面及 YUYV 预览可用；配置并发、断流、保护及会话回收行为通过测试。

## 9. 实施顺序与完成判据

1. A：配置模型、绑定和迁移规则，先锁定话题与帧语义。
2. C、D：打通公开驱动构建、原生 YUYV、消息校验和标定接口。
3. B、E：完成动态三机编排、结构化控制及统一保护。
4. F：让界面和调试预览使用相同配置与控制入口。
5. G：完成离线回归、镜像检查、受控三机和消费链路验收。

测试随各修改包提交，不留到最后集中补写。发布启用前必须同时满足：

- 三台设备同时出流并通过公开消息契约。
- 实际话题、帧、时间与标定绑定和受控验收记录一致。
- 消费方原有录制与后处理完成端到端兼容验收。
- 保护、并发操作及故障恢复没有绕过路径。
- 公开文件与工件通过信息审查。

未完成真机或消费链路验收时，只能标记“离线实现通过”，不能标记“集成完成”。本清单不附任何现场配置或验收数值。
