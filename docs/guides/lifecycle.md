# 生命周期与录制保护

CLI、Web 和 systemd 共用配置校验、操作锁和受检启停路径。
正式启动要求有效档位确认以及满足接口契约的镜像；能力缺失或摘要不符返回
`IMAGE_CONTRACT_UNSUPPORTED`，镜像声明不能替代实际出帧检查。

## 不可变生成版本

根目录 `compose.yaml` 只负责管理服务的引导。正式相机部署从受控 inventory 生成，保存在被 Git 忽略的 `state/generations/`，不覆盖公开示例或用户自建配置。

每个版本包含 Compose、启用设备的驱动 YAML、健康检查、显式绑定及清单。目录和文件采用限制访问权限；清单记录源配置摘要和生成文件摘要。`state/current-generation.json` 是唯一当前指针。

生成顺序为：校验已保存配置，写入临时目录，校验全部 Compose 服务，复查源配置未变化，完成目录落位，最后原子切换指针。任一步失败都不会激活半份配置；失败产物只清理本次创建的受管目录。旧版本保留以供受控诊断，不自动清理未知文件。

相同源配置、草稿状态和有效生成内容的重复生成直接复用当前版本。草稿可用于查看结构；无启用设备时仅生成管理服务，不能作为正式采集版本。

## 话题、帧与设备身份

生成器只采用显式命名空间，不通过逻辑位置推断话题。彩色、深度和对应内参保留公开接口模板，配置请求保持 YUYV 与原始深度。

schema v2 通过组件启动适配器分别传入 ROS 命名空间和驱动的坐标系前缀；设备管理名称不决定实际 ROS 名称。同一命名空间下的相机数据与节点服务保持绑定，TF 使用相应光学帧标识及 ROS 的标准 TF 传输语义。

禁用设备不创建驱动服务，禁用流不进入健康探针。设备计数、配置文件、Compose 服务、依赖和启动顺序来自同一启用列表，按逻辑标识稳定排序，不按 USB 枚举顺序分配。

采集容器使用生成配置的受控用户身份读取私有文件，并把可写运行目录放在临时文件系统中，保持镜像与配置挂载只读。

## 启动与重复调用

CLI、Web 生命周期任务和 systemd 共同进入检查式启动路径：

1. 获取共享锁并检查录制保护。
2. 核对 inventory 与当前版本；切换版本前必须显式停止旧驱动及调试预览。
3. 核对设备绑定、镜像来源和接口能力，不通过额外 SDK 实例打开相机。
4. 对未运行的服务执行配置验证，按确定顺序逐台启动。
5. 每台必须通过实际出帧检查后再继续下一台。
6. 对全部必需流再次检查，并复查实际运行实例，才报告整组就绪。

同一版本已健康运行时不先停机、不重新创建驱动，只重新检查实际流。部分相机已健康时可保留并继续检查其余设备。发现旧版本、重复身份或不健康的运行实例时，不执行隐式重启，要求显式维护恢复。

任何失败都记录 `ready=false`、稳定错误分类和各步骤结果；已启动实例保留供受控诊断，不把部分成功报告为全部成功。原始异常、设备标识与参数不进入这份结构化结果。

schema v2 的图像探针同时检查声明的编码、尺寸、载荷布局、光学帧与时间戳推进，避免配置请求为 YUYV、实际发布其他格式却仍报告健康。深度尺度与标定的完整验证仍属于后续验收。

## 停止与移除

停止操作依据实际容器的项目、角色和实例标签发现设备，而不是遍历正在编辑的 inventory。即使设备已被禁用、删除、改名或生成指针损坏，仍可停止旧驱动；不会停止其他项目、管理容器或临时探针。

重复停止保持安全。单台停止失败后继续处理其他相机，汇总失败并保持整组未就绪。停止整组服务时，先处理预览与相机，全部成功后才停止管理服务，以保留故障诊断入口。

`deploy.sh stop/down` 使用同一锁与保护检查的临时管理助手，避免先杀管理进程再无条件停止相机；助手自身不是待停止的正式管理实例。移除仅针对受管实例，不使用跨配置的无条件 orphan 清理。

## 录制保护与并发

所有配置写入、生成、迁移应用、镜像构建、正式启停、调试预览及开机恢复都遵循同一文件锁和录制保护。线程内允许嵌套调用；其他线程或进程得到 `CONTROL_BUSY`。

获得保护前必须核对当前版本、全部实际运行实例和实际图像健康。保护记录保存到受控状态目录，释放凭证仅交给调用方，不写入日志或录制结果。

受控调用方可使用以下接口，凭证和输出不得公开或提交：

```sh
geminidepthport protect
geminidepthport release-protection
```

释放命令从标准输入接收凭证，避免将凭证放入命令参数。持有方负责在录制明确结束后释放；保护没有自动过期机制。管理进程重启、持有方失联、保护文件损坏均不会自动解除保护并中断采集。凭证丢失或状态损坏时，必须在受控维护流程确认录制结束后处理，不能直接删除记录继续启动。

主机部署脚本同样使用共享锁并在维护前检查保护。只读状态与诊断查询不会解除保护。绕过本工具直接操作 Docker 或宿主机不属于该互斥机制的管理范围。

## 通信与验收

支持的通信档为 ROS Humble、Fast DDS、同机 UDP 和独立 IPC。schema v2 的
`communication.profile` 选择已支持的档案，不支持的组合会拒绝。
Rust 后端与消费者的传输设置见[消费接入](consumer-integration.md)。

健康检查不认证物理深度精度、硬件曝光同步或业务录制完整性。
实际验证范围见[验证索引](../validation/README.md)。
